# Web infrastructure design

تصميم بنية تحتية لموقع ويب، خطوة بخطوة: نبدأ بسيرفر واحد يحمل كل شيء،
وننتهي بنظام موزّع ومؤمَّن ومراقَب ومقسّم إلى طبقات.

## المفاهيم

| المفهوم | الشرح |
| --- | --- |
| Server | جهاز — حقيقي أو افتراضي — يشغّل برامج تنتظر طلبات من العملاء وتردّ عليها |
| Domain name | اسم مقروء للبشر يُترجَم إلى عنوان IP. الناس تحفظ `foobar.com` لا `8.8.8.8` |
| سجل A | سجل DNS يربط اسماً بعنوان IPv4. و `www` في `www.foobar.com` هو سجل A |
| Web server | Nginx — يستقبل طلبات HTTP، يخدم الملفات الثابتة، ويمرّر الديناميكي |
| Application server | يشغّل كودك: المنطق، القوالب، الاستعلامات |
| Database | MySQL — يخزّن البيانات بشكل دائم ويجيب على الاستعلامات |
| TCP/IP | IP يوجّه الحزم، و TCP يضمن وصولها كاملة ومرتّبة |
| Load balancer | HAproxy — مدخل واحد يوزّع الطلبات على عدة سيرفرات |
| Round Robin | خوارزمية توزيع: كل طلب جديد يروح للسيرفر التالي بالدور |
| Active-Active | كل العُقد تخدم الطلبات في نفس الوقت |
| Active-Passive | عقدة واحدة تخدم والثانية احتياط تتولى عند العطل |
| Primary-Replica | الـ Primary وحده يقبل الكتابة، والـ Replica ينسخ تغييراته ويخدم القراءة |
| SPOF | نقطة فشل وحيدة — مكوّن لو وقع، وقع النظام كله |
| Firewall | يرشّح حركة الشبكة ويقلّص سطح الهجوم إلى المنافذ الضرورية فقط |
| HTTPS / SSL | يشفّر الحركة ويثبت هوية السيرفر ويمنع التلاعب بالبيانات |
| Monitoring | وكيل على كل جهاز يجمع المقاييس والسجلات ويرسلها لخدمة مراقبة |
| QPS | عدد الطلبات في الثانية — يُشتق من سجل وصول Nginx |

## المهام

| الملف | التصميم |
| --- | --- |
| `0-simple_web_stack` | سيرفر واحد: Nginx + تطبيق + كود + MySQL |
| `1-distributed_web_infrastructure` | موزّع: HAproxy + سيرفرين + عنقود Primary-Replica |
| `2-secured_and_monitored_web_infrastructure` | + 3 جدران نارية + شهادة SSL + 3 وكلاء مراقبة |
| `3-scale_up` | + موازن ثاني كعنقود + فصل كل مكوّن على سيرفر خاص |

كل ملف يحتوي على: شرح تدفّق الطلب، سبب إضافة كل عنصر، الإجابات على أسئلة
المشروع، ومشاكل تلك البنية. وبجنب كل ملف صورة PNG للمخطّط.

## المشاكل التي يحلّها كل تصميم

```
0  →  SPOF، توقّف عند النشر، لا يتوسّع
1  →  حلّ التوسّع، بقي: SPOF في الموازن و Primary، لا أمان، لا مراقبة
2  →  حلّ الأمان والمراقبة، بقي: SSL ينتهي عند الموازن، كتابة واحدة، مكوّنات متزاحمة
3  →  حلّ تزاحم المكوّنات و SPOF الموازن بفصل الطبقات وعَنقَدة HAproxy
```

## ملاحظة
